# chinese_subtext —— Echo 中文潜台词解码器 · 语料库 V1

本仓库是 Echo 项目的种子语料库，用于训练和评测「中文潜台词解码」能力：
把一句日常应答（如「行吧」「算了」「随便」）还原成字面义、真实意图、情绪与得体替代回复。

## 文件

| 文件 | 说明 |
|---|---|
| `corpus_v1.json` | 10 条种子样本，覆盖 5 个高危词：行吧 / 算了 / 随便 / 改天 / 再看看 |
| `README.md` | 本文件 |

## `corpus_v1.json` 结构

严格的 JSON 数组，每个元素字段固定为：

```json
{
  "id": 1,
  "scene": "宿舍",
  "dialogue": [
    {"speaker": "对方", "text": "原话"},
    {"speaker": "我", "text": "回应"}
  ],
  "target_phrase": "行吧",
  "literal": "字面英文",
  "intent": "真实意图",
  "emotion": "情绪",
  "alternative": "得体回复"
}
```

- `dialogue` 固定两轮，顺序为「对方」→「我」。
- `target_phrase` 是高危词，出现在「我」的回应里。
- `literal` 是该回应在语境下的字面英文直译。
- `alternative` 是同一处境下更得体、不依赖潜台词的表达。

## 数据来源说明（重要）

原始计划是从开源闲聊语料中「提取」含上述高危词的双人对话，实际执行后发现语料不满足要求：

- **豆瓣多轮**（`MarkWuNLP/MultiTurnResponseSelection`，test.txt，1000 条去重对话）：
  是论坛问答串，五个词合计仅 9 处命中，且是标题式提问而非双人对话。
- **小黄鸡语料**（`candlewill/Dialog_Corpus`）：命中量足够（算了 836、随便 486、
  改天 54、行吧 39、再看看 5），但上下文随机、多为机器人应答，不存在可标注的真实潜台词。

因此 V1 的 10 条样本为**人工撰写的种子样本**，场景与话术参照中文日常语用的常见模式，
不是从上述语料直接抽取的原文。后续版本应替换为真实采集并双人标注的数据。

## 已知局限

1. 规模仅 10 条，只能作为格式基准与回归测试，不具备训练价值。
2. 场景集中在宿舍 / 办公室 / 情侣 / 社交 / 求职 / 消费六类，未覆盖家庭长辈、上下级等高风险场景。
3. 只有一个标注者，`intent` 与 `emotion` 无标注一致性数据。

## 许可

自有内容，随项目许可发布。第三方语料（豆瓣多轮、小黄鸡）未纳入本仓库，
再次分发前需单独确认其许可。

## V2 更新：扩充到 20 条

`corpus_v1.json` **一个字节没改**，仍然可用。V2 是在它之上另建一层：
新增 10 条自撰语料，并给全部 20 条加一个 `device` 标注（这条潜台词靠什么话语策略产生）。

规模：20 条 / 12 个高危词 / 18 个场景。新增条目重点补上了「已知局限 2」点名的缺口——
家庭长辈（11 / 14 / 18）、上下级与师生（12 / 15 / 16 / 19）、亲戚（17）。
`行吧`、`算了`、`再看看` 各有 3 个场景，用来演示「同一句话，换个场合意思就变」。

### 关于「参考开源项目」

标注体系（`device` 七分类 + 与 Gricean 准则的对应）参考了上海交大开源语用数据集
**SwordsmanImp**（`sjtu-compling/llm-pragmatics`，200 段《武林外传》）的方法论。
但该仓库**没有 LICENSE，剧本本身另有版权**，所以**没有使用它的任何条目原文**，
新增的十条全部为本项目自撰。分类定义见 `SCHEMA.md` 第二节。

### 回滚

`corpus_v1.json` 始终未被修改，恢复 V1 只需删除 `corpus_v2.json` 与 `translations.json`，
保留 `corpus_v1.json` 与本文档即可。

## V3 更新：合并三套语料，统一格式（147 条）

V2 的 20 条 + 组员提交的 `chinese_subtext_corpus.json`（27 条）+ `pragmatic_cards.json`（100 条）
合并为一份，**所有原始语句一字未改**，只补字段、归一场景、统一 `alternative` 口径。

规模：**147 条 / 131 个核心词 / 12 个场景大类 / 16 种人物关系**，`device` 扩到 11 类。
`行吧`（4 个场景）、`再看看`（4 个）、`算了`（3 个）、`随便`（3 个）用来看「同句异景」。

### 用法

```bash
python v3/merge_v3.py     # 合并（改完标注表要重跑）
python verify_v3.py       # 自检，11 项，全绿再提交
```

本地开发副本把这些文件放在 `corpus/` 子目录下，命令相应加 `corpus/` 前缀即可，
两种结构等价。组员提交的两个源文件（`chinese_subtext_corpus.json` / `pragmatic_cards.json`）
就放在根目录，`merge_v3.py` 会自动在那里找。
`sync_corpus.py`（把语料转成前端用的 `corpus.js`）服务于站点，不在本仓库。

### 与 V2 的口径差异

1. **取消「必须对方先说」**。真实对话里我先开口很常见，旧规则把 27 条里的 4 条判成了错误。
   现在用 `target_speaker` 记录目标短语落在谁嘴里：`self` 是「我」说的，`other` 是对方说的。
2. **`target_phrase` 可以是一整句**（如「不了不了，我喝不下了」），
   另设 `core_word`（如「不了不了」）供词卡与「同句异景」归类使用。
3. **`alternative` 只保留台词**。原 27 条混着「听出TA其实不情愿：『…』」这类策略说明，
   教学时没法直接照着说，已逐条改写；原本的意思在 `intent` 里。
4. **`device` 从 7 类扩到 11 类**。合并进来的 127 条里，「借客观理由婉拒」「拖延不表态」
   「受夸谦辞」占了大头，7 类覆盖不了，硬塞会误导标注。

### 需要后续处理

- **`sincere`（25 条）**：真诚道歉、道谢、答应，字面即本意，本来不需要解码。
  为不把它们硬归成「过度客气」单列了一类，属于**待替换项**，后续应换成真有潜台词的场景。
- **127 条缺英日讲解**：英文界面目前回落中文。补齐前不建议对外展示英文版。
- **人物关系有 5 条是推断的**：`c27#4 / #12 / #13 / #16 / #21` 的对话里看不出确切关系
  （恋人还是室友、家人还是配偶），现按上下文取了最常见的一种，需要组里确认。

### 回滚

删掉 `corpus_v3.json` 与 `v3/` 目录即可回到 V2；
`sync_corpus.py` 会在没有 V3 时自动回落读 V2，`corpus_v1.json` 不受影响。
